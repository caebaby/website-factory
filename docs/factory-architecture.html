06 — What Would Genuinely Improve Quality / Cost / Speed

1. Parallel Stages in factory.js

PROCESS.md says "01+02 together; 03 parallel with 02.5" but factory.js runs sequentially. Wire parallel spawns — same models, same outputs, ~40% faster wall-clock.

Impact: ⏱ -40% build time | Quality: same | Effort: 1 day code change

2. Budget Guardrail

Add per-client cost cap to factory.js. If cumulative spend exceeds threshold, pause + alert. Prevents the $50 build that should cost $5.

Impact: 💰 prevents runaway spend | Quality: same | Effort: 2 hours

3. Screenshot Review Service

Auto-generate mobile + desktop screenshots at breakpoints after gauntlet. Review gates get faster — see rendered result without opening browser. Johnny can review from phone.

Impact: ⏱ faster reviews | Quality: same | Effort: half day

4. Reveal Animation Pattern in Docs

The Kimi-K3 defect that stalled the gauntlet? Every model hits it until the warm-premium transition pattern is a REQUIRED pattern in COMPONENTS.md. One doc update prevents a whole defect class.

Impact: ✅ fewer repair loops | Cost: fewer wasted tokens | Effort: 1 hour

✗ Don't: GitHub Actions Auto-Build

You'd review the output anyway. HITL gates mean you're involved regardless. Adds infrastructure complexity without payoff.

Impact: complexity without payoff

✗ Don't: Build Intake Form Automation Yet

Manual intake works at 2-5 clients. Build the form when intake becomes a bottleneck — not before. Premature automation locks in a process you're still refining.

Impact: premature lock-in
07 — Is This the Simplest Effective Process?

Yes — If You Avoid Two Traps

The system is already simple: GitHub is the file system, factory.js is the engine, Hermes routes the models. Three moving parts. Everything else is files.

  • One repo, two layers (factory code + client work)
  • factory.js orchestrates — no LangChain, no workflow framework
  • HITL gates are PRs / approval commands, not infrastructure
  • Cost tracking reads from existing Hermes session data
  • State is a JSON file per client — resume from anywhere
  • Don't add GitHub Actions to auto-trigger builds (you'd review anyway)
  • Don't separate the factory from the projects into multiple repos
  • Don't build an intake form automation until manual intake breaks
  • Don't add LangChain, workflow engines, or orchestration frameworks

Rule of thumb: if a new piece of infrastructure doesn't make the pipeline faster, cheaper, or higher quality — it's complexity without payoff. The current design has three ingredients. Keep it there until one of them breaks.
